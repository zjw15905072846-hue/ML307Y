2026-09-30 离线待机实现记录。代码、模拟测试和构建已完成；真实休眠、按键唤醒、电流及新固件平台交互尚未验收。

报警普通构建现已默认开启离线待机并选择 SDK DEEP，业务结束后停止 MQTT、关闭射频；当前私有配置心跳为八小时；这不等于已经确认实板低功耗。前台和后台并行，图中的 ↓ 表示执行顺序，→ 表示请求、结果或跳转；失败路径不能汇入成功步骤。

## 时间和业务边界

- 首次注册业务确认后发送首次心跳。之后从上次心跳业务成功回执开始计时；当前八小时，周期由私有宏配置。报警、重连与进入休眠都不重置该起点。
- 运行期间，周期心跳让位于待处理报警；已经发出的控制业务仍按原序号处理回执及超时。MQTT PUBACK 不能删除报警。
- 没有待处理报警时，注册／心跳一轮尝试120秒；关闭耗时另外记录，成功离线后再等900秒。SDK调用执行期间不会强行终止调用；在下一次状态机检查预算后转入关网。
- 未确认报警、保存失败、删除失败及控制序号持久化失败均保持唤醒。信号差或平台不确认报警时，仍可能持续耗电。
- 按键前1秒灯常亮且静音，随后3秒按250ms开／250ms关闪鸣；前4秒不可被回执打断，之后按原规则最多再亮30秒。旧事件回执不结束新提示，稳定释放后重按新增事件。
- 离线按键先采集本次电池电压并保存，不等射频或SIM身份读取。离线时未知的信号／时间不伪造成实测值，仍按既有遥测和历史补报配置处理。
- 保留UART0，待机不承诺整板仅按键耗电。射频关闭期间不能即时接收平台下行；按键上传增加恢复网络的延迟。
