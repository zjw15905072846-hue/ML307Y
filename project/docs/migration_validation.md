## 验收覆盖与实际限制

- **按键与提示**：抖动、按住不重复、释放重按、完整六个周期；0.5／2／4／10／34 秒附近确认；最新提示归属；34 秒后继续保留和重试。
- **前后台隔离**：模拟后台长时间未完成保存时，前台仍执行提示；保存请求映射持久事件；旧保存结果、旧确认和旧静止通知不能完成新事件或许可错误休眠；后台任务创建失败明确通知前台。
- **协议闭环**：主机使用真实帧编码、CRC、AES-CBC 和会话解析，覆盖注册/心跳序号与报警序号隔离、平台拒绝、重复和过期确认、删除失败保留。测试使用虚构身份/密钥，未发送网络消息。
- **传输适配**：CM 头文件配合单线程回调模型，覆盖 SUBACK 上线门控、分段和深拷贝、过期连接代数、队列拥塞、恢复连接、超时、迟到/重复 PUBACK。模型不能证明真实 RTOS 调度和 SDK 内部回调竞态。
- **持久化**：空白、最新代数、截断/CRC 损坏恢复、外来身份/版本、I/O 失败、短写、零写、同步/关闭失败、回读不一致、队列满、确认删除失败。故障模型验证旧完整快照不被覆盖；真实 LittleFS 掉电原子性仍需上板切电。
- **产品与资源**：显式源文件选择、厂商示例入口互斥、重复资源/ID/命名空间、错误板和平台、越界路径、底包导出表混用、独立缓存、生成配置依赖、模板生成不覆盖既有产品。
- **排版**：先保存 pre-format.zip，再逐批格式化自研代码，前后运行同一套主机回归；测试用第三方依赖与厂商文件没有全局格式化。

## 本轮发现并处理的问题

先保留失败测试或失败编译日志，再修复并回归：

1. 厂商构建图未把 MAP 明确声明为 ELF 链接副产物，且底包链接未依赖响应文件；补上依赖，使并行任务顺序正确。
2. 绝对源节点绕过产品 VariantDir；改为 project 内相对源路径，清理本轮误生成的五个源目录对象文件。
3. 当前 CM GPIO 模式枚举与旧习惯不同；依据新头文件使用受支持的占位模式，仍保留引脚核验门控。
4. 队列层把底层外来格式/损坏状态合并为 I/O 错误；现在保留明确错误类别，不触发清空。
5. MQTT 回调队列满后，旧 SUBACK 可能让已断开的连接重新上线；现在作废旧代数并限制订阅确认阶段。
6. 后台任务创建失败只打印日志，未通知前台；现在投递本地故障消息。
7. 清单名称未检查、私有配置宏头未进入依赖图，以及 Windows 参数引号丢失；分别加清单校验、显式依赖与生成转接头，并完成实际配置构建验证。
